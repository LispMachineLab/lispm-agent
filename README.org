#+title: LispM — a Lisp Machine for agents
#+startup: content

#+HTML: <p align="center"><img src="assets/logo/lispm-mark-dark-v5.png" alt="LispM emblem" width="200" /></p>

LispM runs AI agents inside Emacs rather than beside it. You talk to an agent in a chat
laid out like Claude Code's; underneath, the conversation is stored as an org document that is
also the agent's context, tools are Elisp functions, approvals are org TODO states, memory is
org files under git, and agents are woken by Emacs hooks and delegate work to each other. See
[[file:DESIGN.org][DESIGN.org]] for the design.

The name comes from the Lisp Machine (LispM): an environment where everything was a live Lisp
object and the editor and the system were one. Back then its inhabitants were programs; here
they are agents. In code, the package name and prefix are all lowercase: ~lispm~.

* Installation

Requires Emacs 29.1+ (developed on 31.1), curl, and a model endpoint speaking either the OpenAI
Chat Completions API (most servers do) or the Anthropic Messages API. By default LispM uses the
local Rotom gateway (1.5.15 or later) through Chat Completions (~http://127.0.0.1:14550/v1~,
model ~gpt-5.5~).

#+begin_src emacs-lisp
(add-to-list 'load-path "~/src/lispm")      ; git clone https://github.com/RyanKung/lispm
(require 'lispm)
(lispm-mode-line-mode 1)          ; show busy agents and pending approvals in the mode line
#+end_src

* Getting started

LispM is used the way Claude Code and Codex are: an agent works in a project, one
conversation per agent, and you can run several and come back to any of them.

1. In any project, ~M-x lispm~ starts a new agent there and opens its chat (role
   ~assistant~; ~C-u M-x lispm~ picks another role). Start as many as you like.
2. Type at the ~λ >>~ prompt at the bottom (~lispm-chat-prompt~) and press ~RET~; ~S-RET~ or
   ~C-j~ starts a new line, ~M-p~ / ~M-n~ recall what you sent. Messages sent while the agent
   works are queued.
3. The reply streams in above the prompt: what the agent says (~⏺~), each tool call as
   ~⏺ Read(file)~ with a one-line result (~TAB~ on it shows it in full), edits as diffs. A
   call that needs approval opens a box with the command or diff and the model's reason;
   answer ~1~ (yes), ~2~ (yes, and don't ask again for that tool) or ~3~ (no, and say what
   to do instead), or pick with the arrow keys and ~RET~.
4. ~C-c C-c~ interrupts. ~/~ starts a command (~/help~ lists them): ~/clear~, ~/compact~,
   ~/resume~, ~/model~, ~/diff~, ~/undo~, ~/memory~, ~/cost~, ~/agents~, ~/transcript~,
   ~/exit~.
5. Killing the chat ends the agent; its session stays on disk, and ~M-x lispm-resume~ brings
   back any recorded session (those of the current project first).

| Key                 | In the chat                                                      |
|---------------------+------------------------------------------------------------------|
| ~RET~               | send; with nothing written, answer the approval prompt           |
| ~S-RET~, ~C-j~      | new line                                                         |
| ~TAB~               | show the item at point in full, or briefly again; complete ~/~   |
| ~1~ ~2~ ~3~         | answer the approval prompt                                       |
| ~M-p~, ~M-n~        | previous and next message sent                                   |
| ~C-c C-c~           | interrupt the agent                                              |
| ~C-c C-t~           | open the org transcript                                          |

| Command                | What it does                                                       |
|------------------------+--------------------------------------------------------------------|
| ~lispm~                | start a new agent in the current project                           |
| ~lispm-resume~         | resume a recorded session                                          |
| ~lispm-switch~         | switch to a running agent                                          |
| ~lispm-new-session~    | a fresh session like the current one: same role, same project      |
| ~lispm-compact~        | hand the session over to a continuation holding a summary          |
| ~lispm-ask~            | give the project's agent a request from the minibuffer             |
| ~lispm-ask-region~     | ask the project's agent about the region                           |
| ~lispm-dashboard~      | every agent's state, pending approvals, inbox and token usage      |
| ~lispm-agenda~         | calls awaiting approval across all sessions (org agenda)           |
| ~lispm-review~         | review pending calls (~C-c C-y~ in an org transcript)              |
| ~lispm-turn-diff~      | show what an agent changed in its last turn                        |
| ~lispm-revert-turn~    | undo every edit an agent made in its last turn                     |
| ~lispm-show-request~   | show the full request that will be sent to the model next          |
| ~lispm-history~        | git history of memory, tasks and sessions                          |

** The org transcript

The chat is only the interface. The conversation itself is an org document under
~lispm-directory~, and that document is the context: every request is built from it, and the
chat is redrawn from it whenever it changes. ~/transcript~ (~C-c C-t~) opens it. Delete a
subtree and the agent forgets it; tag a message ~:ignore:~ and it is no longer sent; headings
of your own, such as ~* Notes~, are private annotations. Tool calls are TODO entries
(~WAITING~, ~DONE~, ~DENIED~, ...), so changing a waiting call's state approves or denies it,
and ~M-x lispm-agenda~ lists every call awaiting approval.

To work in the org document directly instead of the chat, set ~lispm-interface~ to ~org~:
write under the last ~* User~ heading, send with ~C-c RET~, review calls with ~C-c C-y~, abort
with ~C-c C-k~.

* Agents, roles and sessions

- A *role* is a kind of agent: instructions, tools, permission policy, model. ~assistant~ is
  built in; define more with ~lispm-defrole~.
- An *agent* is one conversation carried on by a role in one project: agent and session are
  the same thing. Its name is ~ROLE@PROJECT~ (~assistant@lispm~, ~assistant@lispm<2>~, ...).
- A project's ~AGENTS.md~ and ~CLAUDE.md~ join its agents' system prompt, so a project set up
  for Codex or Claude Code needs nothing more.
- A conversation that grows long is handed over before the next turn: the agent first saves
  what should outlive it to memory and tasks, then writes a summary, and the conversation
  continues in a new file that starts from the summary and links back to the old one
  (~lispm-compact-threshold~; ~M-x lispm-compact~ does it on demand).
- Everything lives under ~lispm-directory~ (~/.emacs.d/lispm/~), a git repository:
  ~projects/<project>/sessions/~, ~projects/<project>/memory.org~ and ~tasks.org~ (shared by
  the project's agents), and ~roles/<role>/memory.org~ (what a role learns everywhere).

#+begin_src emacs-lisp
(lispm-defrole reviewer
  "Reviews changes for bugs; never edits."
  :tools '(read_file search_files list_directory read_buffer recall remember send_message))
#+end_src

Permission classes: ~read~, ~memory~ and ~comm~ run automatically by default; ~write~ and
~exec~ need approval (see ~lispm-default-policy~).

* Standing agents

Agents declared in your configuration are *standing*: each keeps one conversation going, which
it resumes after Emacs restarts, and hooks and timers can wake it up.

#+begin_src emacs-lisp
(lispm-defagent coder
  "Writes and fixes Emacs Lisp in this repository."
  :root "~/src/lispm/"
  :instructions "Keep changes small. After editing, run `make test` and report the result."
  :policy '((write . auto)))          ; writes inside the root run without asking (outside, they still ask)

;; Wake coder when a compilation fails.
(lispm-watch 'coder 'compilation-finish-functions
  :when (lambda (_buffer status) (string-match-p "abnormally" status))
  :prompt "The compilation failed. Read *compilation*, find the cause and fix it.")

;; On a timer.
(lispm-every 'coder 3600 "Look at your open tasks and move one forward.")
#+end_src

Agents collaborate through ~ask_agent~ and ~send_message~. ~ask_agent~ delegates to a running
agent and waits for its reply; given a role instead, it starts a helper of that role in the
same project, which retires once it has replied (a subagent). Project task lists can join your
agenda: ~(setq org-agenda-files (append org-agenda-files (lispm-agenda-files)))~.

* Backends

LispM speaks two API shapes: OpenAI Chat Completions, which almost every model server
implements, and Anthropic Messages. A backend names an endpoint, its shape and the features to
use. The presets:

| Backend          | Shape            | URL                         | Default model     | Key                 |
|------------------+------------------+-----------------------------+-------------------+---------------------|
| ~rotom~ (default)| Chat Completions | ~http://127.0.0.1:14550/v1~ | ~gpt-5.5~         | none                |
| ~rotom-messages~ | Messages         | ~http://127.0.0.1:14550~    | ~gpt-5.5~         | none                |
| ~openai~         | Chat Completions | ~https://api.openai.com/v1~ | ~gpt-5.5~         | ~OPENAI_API_KEY~    |
| ~anthropic~      | Messages         | ~https://api.anthropic.com~ | ~claude-opus-5-5~ | ~ANTHROPIC_API_KEY~ |

#+begin_src emacs-lisp
(setq lispm-backend 'anthropic)             ; use another preset
(setq lispm-model "grok-4.6")               ; another model (list rotom's with `rotom models`)

;; Any other Chat Completions server: Ollama, vLLM, LM Studio, llama.cpp, OpenRouter, ...
(add-to-list 'lispm-backends
             '(ollama :api openai :url "http://localhost:11434/v1"
                      :model "qwen3-coder"          ; a model you have pulled
                      :features (streaming)))
(add-to-list 'lispm-backends
             '(hosted :api openai :url "https://example.com/v1"
                      :model "model-name" :key-env "EXAMPLE_API_KEY"
                      :features (streaming reasoning-effort)))
#+end_src

Each agent can also set its own ~:backend~, ~:model~ and ~:effort~, so agents on different
providers can work together. ~C-h v lispm-backends~ documents every option; section 9 of
DESIGN.org explains the translation between the shapes.
